# Screens

## 1. 全体方針

UI・ページ構成は `https://www.setups.site/` を参考にする。

Minecraft建築作品を画像中心のギャラリーとして表示し、ユーザーが作品を次々に発見できるUIを重視する。

デザインは参考サイトをそのままコピーせず、Minecraft建築サービスとして独自に構成する。

---

## 2. 共通レイアウト

### Header

全ページ共通で表示する。

左側：

- サービスロゴ

中央：

- 検索ボックス

右側：

- 投稿ボタン
- Xログイン / ユーザーメニュー

### Footer

以下を表示する。

- About
- 利用規約
- プライバシーポリシー
- お問い合わせ

---

## 3. Home `/`

サービスのメイン画面。

### 構成

1. Header
2. メインビジュアル
3. 注目作品
4. 新着作品
5. 人気タグ
6. Footer

最も重要な画面。

作品画像を大きく表示し、テキストよりも作品そのものを目立たせる。

---

## 4. Build List `/builds`

建築作品を一覧表示する。

### 構成

1. Header
2. ページタイトル
3. 検索・フィルター
4. 作品グリッド
5. 追加読み込み
6. Footer

### 作品カード

各カードには以下を表示する。

- 建築画像
- 説明
- 作者名
- いいね数

カード全体をクリックすると作品詳細へ移動する。

画像を主体としたカードデザインにする。

---

## 5. Build Detail `/builds/[slug]`

作品を詳しく閲覧する画面。

### 構成

1. Header
2. メイン画像
3. 追加画像
4. 作品タイトル
5. 作者情報
6. 説明
7. タグ
8. いいね / 共有
9. コメント
10. 関連作品
11. Footer

### 作者情報

作者名・プロフィール画像を表示する。

クリックするとユーザーページへ移動する。

### 画像

複数画像がある場合、メイン画像＋サムネイル形式で表示する。

画像クリックで大きく閲覧できる。

---

## 6. Create Build `/builds/new`

建築作品を投稿する画面。

### 構成

1. Header
2. 画像アップロード
3. 作品タイトル
4. 説明
5. タグ
6. 投稿ボタン

画像はドラッグ＆ドロップまたはファイル選択でアップロードできる。

アップロードした画像を投稿前にプレビューする。

投稿完了後は作品詳細ページへ移動する。

---

## 7. Edit Build `/builds/[slug]/edit`

自分の作品を編集する画面。

Create Buildと同じフォーム構成にする。

既存の画像・タイトル・説明・タグを初期表示する。

保存後は作品詳細ページへ移動する。

---

## 8. User Profile `/users/[username]`

ユーザーのプロフィールと作品を表示する。

### 構成

1. Header
2. プロフィール画像
3. ユーザー名
4. 自己紹介
5. 投稿作品数
6. 作品グリッド
7. Footer

作品グリッドはBuild Listと同じカードデザインを使用する。

本人の場合のみ「プロフィール編集」ボタンを表示する。

---

## 9. Tag `/tags/[tag]`

特定タグの作品を一覧表示する。

### 構成

1. Header
2. タグ名
3. 該当作品数
4. 作品グリッド
5. Footer

作品グリッドはBuild Listと共通コンポーネントを使用する。

---

## 10. Search `/search`

検索結果を表示する。

### 構成

1. Header
2. 検索ボックス
3. 検索キーワード
4. 検索結果件数
5. 作品グリッド
6. Footer

作品タイトル、説明、タグを検索対象とする。

---

## 11. Login `/login`

Xログイン専用画面。

### 構成

中央にログインカードを配置する。

- サービスロゴ
- サービス説明
- 「Xでログイン」ボタン

メールアドレス・パスワードによるログインフォームは作成しない。

---

## 12. User Menu

ログイン後、Headerのユーザーメニューから以下を操作できる。

- プロフィール
- 自分の投稿
- 作品を投稿
- ログアウト

---

## 13. Admin

管理者専用画面。

MVPでは必要最低限の管理機能のみ提供する。

### 管理画面

- 投稿一覧
- ユーザー一覧
- コメント一覧
- 通報一覧

管理者以外はアクセスできない。

---

## 14. Responsive Design

### Desktop

- 大きな作品画像
- 3〜5列程度の作品グリッド
- Headerに検索・ナビゲーションを表示

### Tablet

- 2〜4列程度

### Mobile

- 2列程度の作品グリッド
- コンパクトなHeader
- タップ操作を優先

画面幅に応じてグリッドの列数を自動調整する。

---

## 16. 画面遷移

### 未ログイン

```text
Home
 ├─→ Build List
 │     └─→ Build Detail
 │            └─→ User Profile
 │
 ├─→ Search
 │     └─→ Build Detail
 │
 ├─→ Tag
 │     └─→ Build Detail
 │
 └─→ Login
```

### ログイン後

```text
Login
 ↓
Home
 ↓
Create Build
 ↓
Build Detail
```

Build Detailから、

```text
Build Detail
 ├─→ User Profile
 ├─→ Tag
 ├─→ Like
 └─→ Comment
```

へ移動できる。

---

## 17. UI実装方針

- 画像を最も目立たせる。
- 余白を十分に取る。
- 作品カードはシンプルにする。
- ページごとに異なるUIを作らず、共通コンポーネントを使用する。
- PC・スマートフォンの両方で使いやすくする。
- ローディング状態、空状態、エラー状態を用意する。
- 投稿・削除など重要な操作には確認UIを表示する。
- アクセシビリティを考慮する。
- 必要以上にアニメーションを追加しない。
