# Screens

## 1. 全体方針

UI・ページ構成は `https://www.setups.site/` を参考にする。

Minecraft建築作品を画像中心のギャラリーとして表示し、ユーザーが作品を次々に発見できるUIを重視する。

デザインは参考サイトをそのままコピーせず、Minecraft建築サービスとして独自に構成する。

---

## 2. 共通レイアウト

### Header

全ページ共通で表示する。

左側：

- サービスロゴ

中央：

- 検索ボックス
    - 送信で `/builds?q={キーワード}` に遷移する

右側：

- 投稿ボタン
- 未ログイン時はログインボタン / ログイン時はユーザーアイコン
    - ログインボタンをクリックするとログインダイアログを表示する
    - ユーザーアイコンをクリックするとユーザーメニューを表示する

### Footer

以下を表示する。

- About
- 利用規約
- プライバシーポリシー
- お問い合わせ

---

## 3. Home `/`

サービスのメイン画面。

### 構成

1. Header
2. タグ
3. 注目作品
4. 新着作品
5. Footer

最も重要な画面。

作品画像を大きく表示し、テキストよりも作品そのものを目立たせる。

---

## 4. Build List `/builds`

建築作品を一覧表示する。

### 構成

1. Header
2. タグフィルター(横スクロール可能なチップ行)
3. 並び替えスイッチ(人気順 / 新着順)
4. 作品グリッド
5. 追加読み込み
6. Footer

### URLパラメータ

絞り込みと並び替えの状態はURLパラメータに同期し、URLの共有および再訪時に同じ状態を再現できる。

- `sort`: 人気順(popular) / 新着順(recent)
- `tag`: タグ絞り込み
- `q`: キーワード検索

### 作品カード

各カードには以下を表示する。

- 建築画像
- 説明(1行・強調表示)
- 作者のアバター
- いいね数
- コメント数(いいね数の右隣)

カード全体をクリックすると作品詳細へ移動する。

画像を主体としたカードデザインにする。

---

## 5. Build Detail `/builds/[id]`

作品を詳しく閲覧する画面。

### 構成

1. Header
2. メイン画像
3. 追加画像
4. 作者情報
5. 説明
6. タグ
7. いいね / 共有
8. コメント
9. 関連作品
10. Footer

### 作者情報

作者のニックネームを表示する。

クリックするとユーザーページへ移動する。

### 画像

複数画像がある場合、メイン画像＋サムネイル形式で表示する。

画像クリックで大きく閲覧できる。

---

## 6. Create Build `/builds/new`

建築作品を投稿する画面。

### 構成

1. Header
2. 画像アップロード
3. 説明
4. タグ
5. 投稿ボタン

画像はドラッグ＆ドロップまたはファイル選択でアップロードできる。

アップロードした画像を投稿前にプレビューする。

投稿完了後は作品詳細ページへ移動する。

---

## 7. User Profile `/users/[id]`

ユーザーのプロフィールと作品を表示する。ニックネームの重複を許容するため、URLには内部UUIDを使用する。

### 構成

1. Header
2. ニックネーム
3. 投稿作品数
4. 作品グリッド
5. Footer

作品グリッドはBuild Listと同じカードデザインを使用する。

本人の場合のみ「プロフィール編集」ボタンを表示する。

---

## 8. Tag(タグ絞り込み)

タグは独立したルートを持たず、作品一覧(`/builds?tag={タグ名}`)と共通の画面で表示する。
タグはDBの取得順で表示し、人気順などの並び替えは行わない。

- トップページのタグチップ: `/builds?tag=` に遷移する
- 作品一覧のタグチップ: 画面内でそのタグに絞り込む(選択解除はせず、クリックのたびにそのタグの絞り込みを適用する)

作品グリッドはBuild Listと共通コンポーネントを使用する。

---

## 9. Search(キーワード検索)

検索は独立したルートを持たず、ヘッダーの検索バーから `/builds?q={キーワード}` として作品一覧と共通の画面で表示する。

- 検索対象: 作品説明・タグ・作者名(部分一致、大小文字非区別)
- 検索結果はタグフィルター・並び替えと組み合わせられる

---

## 10. Login Dialog

Googleログイン専用のダイアログ。独立したログインページは持たず、Header のログインボタンから開く。

### 構成

中央にログインカードを表示する。

- サービスロゴ
- サービス説明
- 「Googleでログイン」ボタン
- 閉じるボタン

メールアドレス・パスワードによるログインフォームは作成しない。

### 挙動

- 背景クリック・閉じるボタン・Escape キーで閉じる。
- 表示中は背景のスクロールを停止する。
- 認証に失敗した場合はダイアログ内にエラーメッセージを表示する。

---

## 11. User Menu

ログイン後、Headerのユーザーアイコンからメニューを開き、以下を操作できる。メニューはアイコンの再クリック、またはメニュー外のクリックで閉じる。

- マイページ: ユーザーページ(`/users/{id}`)へ遷移する
- ログアウト: ログアウトしてトップページ(`/`)へ遷移する

---

## 12. Admin

管理者専用画面。

MVPでは必要最低限の管理機能のみ提供する。

### 管理画面

- 投稿一覧
- ユーザー一覧
- コメント一覧
- 通報一覧

管理者以外はアクセスできない。

## 13. Responsive Design

## 15. 画面遷移

### 未ログイン

```text
Home
 ├─→ Build List (sort / tag / q で絞り込み)
 │     └─→ Build Detail
 │            └─→ User Profile
 │
 └─→ Login
```

### ログイン後

```text
Login
 ↓
Home
 ↓
Create Build
 ↓
Build Detail
```

Build Detailから、

```text
Build Detail
 ├─→ User Profile
 ├─→ Build List (tag)
 ├─→ Like
 └─→ Comment
```

へ移動できる。

---

## 16. UI実装方針

- 画像を最も目立たせる。
- 余白を十分に取る。
- 作品カードはシンプルにする。
- ページごとに異なるUIを作らず、共通コンポーネントを使用する。
- PC・スマートフォンの両方で使いやすくする。
- ローディング状態、空状態、エラー状態を用意する。
- 投稿・削除など重要な操作には確認UIを表示する。
- アクセシビリティを考慮する。
- 必要以上にアニメーションを追加しない。
